# Order Processing

End-to-end flow from checkout to customer notification and tracking.

## Order reference format

Generated by `generateOrderReference()` in `src/lib/orders.ts`:

```
DH-{timestamp-base36}-{14-char-alphanumeric}
```

Non-guessable. Used on success page, emails, and `/track-order`.

## Checkout pipeline

```
Cart → POST /api/checkout/create-session
     → savePendingCheckout (UUID pendingId)
     → Stripe Checkout OR staging-complete path
     → checkout.session.completed webhook OR staging-complete
     → buildAndSaveOrderFromPending
     → sendOrderConfirmation (live only)
     → Customer: /order/success?session_id=...
```

### Pending checkout

Stored in `.data/pending-checkout/` or memory (`src/lib/order-store.ts`).

Payload includes: customer, addresses, delivery access, line items, totals, shipping method, agreements, demonstration flag.

Stripe session metadata: `pendingCheckoutId`, `orderReference`.

### Payment paths

| Path | When |
|------|------|
| Stripe Checkout | `STRIPE_SECRET_KEY` set and demo-safe |
| Staging complete | Staging mode, no Stripe URL - client calls `/api/checkout/staging-complete` |

## Webhook order creation

`POST /api/webhooks/stripe`:

1. Verify signature
2. Handle `checkout.session.completed`, `payment_status === 'paid'`
3. Idempotency check on `session.id`
4. Load pending by `metadata.pendingCheckoutId`
5. `buildAndSaveOrderFromPending` → persisted order
6. Email customer if live

Duplicate webhook deliveries return `{ duplicate: true }`.

## Order record fields

Stored order includes:

- Reference, Stripe session ID
- Customer name, email, phone, company, PO number
- Shipping and billing addresses
- Delivery access details
- Line items with SKU, finish, upholstery, configuration, dimensions snapshot, box count, shipping class, safety snapshot
- Subtotal, shipping, tax, total, currency
- Payment status, fulfillment status
- Shipping label/note, tax label/note
- `isDemonstrationOrder` flag

**Card data is never stored.**

## Fulfillment statuses

| Status | Label |
|--------|-------|
| `order-received` | Order received |
| `payment-confirmed` | Payment confirmed |
| `processing` | Processing |
| `preparing-for-shipment` | Preparing for shipment |
| `shipping-review-required` | Shipping review required |
| `shipped` | Shipped |
| `delivered` | Delivered |
| `cancelled` | Cancelled |

Initial webhook path sets `payment-confirmed`. Demo-complete may set `shipping-review-required` when shipping method is quote-required and shipping amount is zero.

Do not display statuses not stored on the order.

## Order success page

`/order/success` must verify payment server-side via `/api/orders/verify-session` - not trust query params alone.

## Order tracking

`/track-order` - customer provides order reference + email.

Rate limited. Returns only matching order's public-safe fields.

Do not fabricate carrier or tracking numbers.

## Confirmation email

Sent via Resend after verified payment (`sendOrderConfirmation`).

Suppressed when:

- Staging mode
- `productionLaunchBlocked`
- Missing `RESEND_API_KEY`

See [email-setup.md](email-setup.md).

## Quote and contact flows

Separate from orders:

- `POST /api/quote` → `sendQuoteNotification` to `CONTACT_EMAIL`
- `POST /api/contact` → `sendContactNotification`

Rate limited via `src/lib/rate-limit.ts`.

## Operational handling (manual)

Post-payment operations are **outside** this codebase (no admin UI):

1. Monitor `CONTACT_EMAIL` and Stripe Dashboard
2. For `shipping-review-required`, quote freight and contact customer
3. Update fulfillment status in order store or future ERP - currently manual file edit or Supabase migration
4. Assembly-required orders: ensure instructions delivered

## Demonstration orders

`isDemonstrationOrder: true` when checkout ran in staging mode. Flag for filtering test data before fulfillment.

## Persistence limitations

Vercel serverless: `.data/` may not persist. Plan Supabase or external OMS for production volume.

## Security

- Webhook signature required
- Checkout rate limiting
- Server-side price revalidation
- Launch gates in live checkout
